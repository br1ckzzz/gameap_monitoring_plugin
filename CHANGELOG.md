# Changelog

Все важные изменения в проекте GameAP WebMonitoring документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), проект придерживается [Semantic Versioning](https://semver.org/).

## [1.0.5] - 2026-09-18

### Добавлено (Added)
- **Канонический короткий публичный URL без `/view`:**
  - Публичная страница мониторинга теперь доступна напрямую по адресу `/api/plugins/monitoring` (и `/api/plugins/monitoring/`).
  - Сохранена 100% обратная совместимость с адресом `/api/plugins/monitoring/view`.
  - В админ-панели и документации обновлены готовые шаблоны обратного прокси (Nginx, Caddy, Apache).
- **Интерактивный логотип на публичной странице:**
  - Логотип и заголовок в шапке стали кликабельной ссылкой: клик сбрасывает активные фильтры серверов и поиск, возвращая на главную страницу мониторинга.
- **Внутриплагинный RAM Micro-Cache (4 сек) и оптимизация под GameAP v4.5.3:**
  - Реализован быстрый in-memory кэш данных `FetchPublicServers` в памяти плагина на 4 секунды с автоматическим сбросом при сохранении настроек.
  - Предотвращает переполнение очереди запросов GameAP (`PLUGINS_ROUTES_MAX_QUEUE`) при одновременных обращениях множества пользователей.
- **Предзагрузка данных в HTML (Zero-latency Initial Render):**
  - Серверная инъекция `window.INITIAL_DATA` при отдаче HTML страницы обеспечивает мгновенное отображение списка серверов без ожидания первого AJAX-запроса.
- **Поддержка доверенного клиентского IP GameAP v4.5.3:**
  - В диагностическом эндпоинте `/diagnostic` задействован заголовок `X-Gameap-Client-Ip` для корректного отображения IP-клиента за прокси.

### Изменено (Changed)
- **Адаптация поведения фронтенда под DoS-защиту GameAP v4.5.3 (HTTP 429 / 503):**
  - При получении кодов ответа 429 (Too Many Requests) или 503 (Service Unavailable) фронтенд корректно учитывает заголовок `Retry-After`, выводит предупреждение о временной нагрузке и делает паузу вместо повторных каскадных запросов к резервным эндпоинтам.
  - Клиентский таймаут запроса серверов увеличен до 9.5 секунд для согласованности с серверным лимитом ожидания в очереди GameAP (`PLUGINS_ROUTES_QUEUE_TIMEOUT = 10s`).

## [1.0.4] - 2026-09-15

### Добавлено (Added)
- **Умное определение и санитизация адресов серверов (Smart Address Resolution):**
  - Поддержка нескольких ключей в поле «Ключ адреса сервера» (`AddressKey`), разделённых запятыми или точками с запятой (например: `public_ip, domain; hostname`).
  - Поддержка перечисления нескольких IP-адресов или доменов в одной переменной сервера с автоматическим выбором валидного публичного адреса.
  - Строгая санитизация и очистка адресов от протоколов (`http://`, `https://`), конечных слэшей, пробелов, XSS, SQL-инъекций и управляющих символов.
  - Поддержка индивидуального переопределения адреса конкретного сервера через настройки плагина.
- **Ручная сортировка серверов (Drag-and-Drop + стрелки):**
  - Возможность перетаскивания строк серверов мышью в блоке «Видимость и порядок серверов» для задания точной последовательности отображения на публичной странице (`server_order`).
  - Дополнительные кнопки перемещения вверх (▲) и вниз (▼) для удобства на любых устройствах.
- **Брендинг: кастомный логотип и фавикон:**
  - Настройка прямой ссылки на изображение логотипа (отображается в шапке мониторинга) и ссылки на фавикон с мгновенным предпросмотром в панели администратора.
  - Динамическая подстановка favicon во вкладку браузера на публичной странице.
- **Сворачиваемые спойлеры в панели администратора:**
  - Блоки предупреждения о безопасности/DDoS и руководства по настройке обратного прокси (Nginx/Caddy/Apache) теперь компактно сворачиваются с сохранением состояния в `localStorage`.

### Исправлено (Fixed)
- **Выравнивание полей в блоке «Основные параметры»:**
  - Оптимизированы подписи на русском языке (`Тема по умолчанию`, `Интервал обновления (сек.)`), исключён перенос строки, ломавший вертикальное выравнивание полей ввода.
  - Добавлены стили `.wm-form-group` с фиксированной высотой элементов (`42px`) и выравниванием по базовой линии.
- **Надёжность копирования адреса (Clipboard API / Fallback):**
  - Добавлен отказоустойчивый fallback через `document.execCommand('copy')` для браузеров и веб-панелей со строгой политикой безопасности (CSP).

## [1.0.3] - 2026-09-13

### Исправлено (Fixed)
- **Пустой список в блоке «Видимость серверов» админ-панели при доступе из внешней сети:**
  - **Причина:** В `admin_bundle.js` использовался устаревший путь `/plugins/web-monitoring/servers` (возвращавший 404 на рабочей панели GameAP). Резервный вызов `/api/servers` блокировался политикой CORS и отсутствием авторизационного токена при доступе через внешние домены, реверс-прокси или мобильные сети. Кроме того, эндпоинт `FetchPublicServers` в Go отфильтровывал скрытые серверы.
  - **Решение:**
    - В модуле Go реализована функция `FetchAllServers`, запрашивающая полный список серверов напрямую из ядра GameAP через `serversRepo.FindServers` без фильтрации скрытых серверов.
    - Ответ `GET /settings` дополнен полями `servers` и `all_servers`, что позволяет админ-панели гарантированно получать список серверов в том же первичном запросе настроек.
    - В `handleServers` добавлена поддержка флага `all=1` (`action=admin_servers`) для отдачи полного списка серверов для администратора.
    - Во фронтенде админ-панели (`admin_bundle.js`) внедрено мгновенное извлечение серверов из ответа настроек, выстроена цепочка резервных запросов к API плагина и обеспечено сохранение списка в `cached_servers`.

## [1.0.2] - 2026-09-13

### Исправлено (Fixed)
- **Ошибка `route not found` при открытии публичной страницы `/api/plugins/monitoring/view`:**
  - **Причина:** В ядре GameAP парсер Base32 (`pkg/plugin/id.go`) ошибочно пытается декодировать ID `monitoring` как число (все буквы слова входят в алфавит Base32). Из-за несовпадения битовой длины (50 бит у 10 символов base32 vs 48 бит у 6 байт) при обратном сжатии ID превращался в `monitorine`, из-за чего функция `extractPluginPath` в GameAP не могла отрезать префикс URL и сбрасывала путь на `/`.
  - **Решение:** В плагине зарегистрирован корневой fallback-маршрут `{ Path: "/", Methods: ["GET", "POST"] }` и реализована умная диспетчеризация запросов. При сбросе пути на `/` плагин корректно отдаёт публичную HTML-страницу мониторинга либо обрабатывает API-запросы по параметру `?action=...`.
- **Отказоустойчивость запросов API во фронтенде:**
  - В `app.js` и `admin_bundle.js` запросы к API дополнены параметрами действий (`?action=servers`, `?action=settings`) и резервной цепочкой fallback-эндпоинтов.
